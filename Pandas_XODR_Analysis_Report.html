2. XODR와 XML 기본 개념

OpenDRIVE의 .xodr 파일은 도로 메시 파일이 아니라 XML 기반의 도로 구조 데이터이다. XML은 태그가 부모·자식 관계로 중첩되므로 나무(Tree) 구조로 해석할 수 있다.

OpenDRIVE └─ road ├─ planView │ └─ geometry ├─ lanes │ └─ laneSection │ ├─ left │ ├─ center │ └─ right ├─ signals └─ objects junction └─ connection └─ laneLink

행과 열

용어의미XODR 분석 예시
Row(행)가로 한 줄road 하나 또는 lane 하나
Column(열)세로 속성road_id, length, junction 등

자주 등장하는 값

항목뜻
junction="-1"해당 road가 교차로 내부 connecting road가 아닌 일반 road임을 의미
lengthroad 또는 geometry의 길이. 기본 단위는 m
sroad 시작점으로부터 해당 요소가 시작되는 누적 거리. 단위 m
hdgHeading, 즉 시작 방향. 단위 라디안

3. Jupyter에서 XODR 읽기

XML 분석을 위해 Python 표준 라이브러리인 ElementTree를 사용한다.

import os
import pandas as pd
import xml.etree.ElementTree as ET

os.chdir(r"D:\xodrJupyter\testPangyo")

tree = ET.parse("Pangyo.xodr")
root = tree.getroot()

print(root.tag)
print(len(root.findall("road")))

5. lanes_df 구성

lane은 road 바로 아래가 아니라 road → lanes → laneSection → left/center/right → lane에 위치한다. 실무에서 lane 타입, 진행차선 수, laneSection 변화, lane 연결 관계를 확인하는 데 사용한다. 

lanes = []

for road in root.findall("road"):
    road_id = road.get("id")

    for section_index, lane_section in enumerate(
        road.findall("./lanes/laneSection")
    ):
        section_s = float(lane_section.get("s", 0))

        for side_name in ["left", "center", "right"]:
            side = lane_section.find(side_name)

            if side is None:
                continue

            for lane in side.findall("lane"):
                lanes.append({
                    "road_id": road_id,
                    "lane_section_index": section_index,
                    "section_s": section_s,
                    "side": side_name,
                    "lane_id": int(lane.get("id")),
                    "lane_type": lane.get("type"),
                    "level": lane.get("level")
                })

lanes_df = pd.DataFrame(lanes)
lanes_df.head()
열의미
road_id차선이 속한 도로 번호
lane_section_indexroad 내 몇 번째 laneSection인지
section_slaneSection 시작 위치
sideleft, center, right
lane_id왼쪽 양수, 중앙 0, 오른쪽 음수
lane_typedriving, sidewalk, shoulder, none 등

6. geometry_df 구성

geometry는 도로 메시가 아니라 road reference line의 설계 정보다. 즉 도로 중심선을 직선, 원호, 완화곡선 등으로 어떻게 이어갈지 설명한다. 

geometries = []

for road in root.findall("road"):
    road_id = road.get("id")

    for geometry in road.findall("./planView/geometry"):
        geometry_type = "unknown"

        if geometry.find("line") is not None:
            geometry_type = "line"
        elif geometry.find("arc") is not None:
            geometry_type = "arc"
        elif geometry.find("spiral") is not None:
            geometry_type = "spiral"
        elif geometry.find("poly3") is not None:
            geometry_type = "poly3"
        elif geometry.find("paramPoly3") is not None:
            geometry_type = "paramPoly3"

        geometries.append({
            "road_id": road_id,
            "s": float(geometry.get("s", 0)),
            "x": float(geometry.get("x", 0)),
            "y": float(geometry.get("y", 0)),
            "hdg": float(geometry.get("hdg", 0)),
            "length": float(geometry.get("length", 0)),
            "geometry_type": geometry_type
        })

geometry_df = pd.DataFrame(geometries)
s
road 시작점에서 해당 geometry가 시작되는 누적 거리.
hdg
geometry 시작 방향. 0 rad는 +X 방향, 약 1.57 rad는 90도 방향.

7. junction_df 구성

현실의 교차로는 공간적 개념이고, XODR의 junction은 들어오는 road와 교차로 내부 connecting road, laneLink를 묶어 관리하는 논리적 데이터 구조다. 

junctions = []

for junction in root.findall("junction"):
    junction_id = junction.get("id")

    for connection in junction.findall("connection"):
        lane_links = connection.findall("laneLink")

        if not lane_links:
            junctions.append({
                "junction_id": junction_id,
                "connection_id": connection.get("id"),
                "incoming_road": connection.get("incomingRoad"),
                "connecting_road": connection.get("connectingRoad"),
                "contact_point": connection.get("contactPoint"),
                "from_lane": None,
                "to_lane": None
            })

        for lane_link in lane_links:
            junctions.append({
                "junction_id": junction_id,
                "connection_id": connection.get("id"),
                "incoming_road": connection.get("incomingRoad"),
                "connecting_road": connection.get("connectingRoad"),
                "contact_point": connection.get("contactPoint"),
                "from_lane": lane_link.get("from"),
                "to_lane": lane_link.get("to")
            })

junction_df = pd.DataFrame(junctions)
열설명
incoming_road교차로로 들어오는 road
connecting_road교차로 내부에서 이동 경로를 구성하는 road
from_lane → to_lane진입차선에서 연결도로 차선으로 이어지는 관계

9. summary_df 종합표

여러 DataFrame을 road_id 기준으로 집계하여, road 하나에 대한 핵심 정보를 한 행에 모은다. 관리자·수석님·데이터수집팀에 보여주기 가장 적합한 표다. 

summary_df = roads_df.copy()

lane_count = lanes_df.groupby("road_id").size()
summary_df["lane_count"] = summary_df["road_id"].map(lane_count)

driving_lane_count = (
    lanes_df[lanes_df["lane_type"] == "driving"]
    .groupby("road_id")
    .size()
)
summary_df["driving_lane_count"] = (
    summary_df["road_id"].map(driving_lane_count)
)

geometry_count = geometry_df.groupby("road_id").size()
summary_df["geometry_count"] = (
    summary_df["road_id"].map(geometry_count)
)

geometry_types = (
    geometry_df.groupby("road_id")["geometry_type"]
    .apply(lambda x: ", ".join(x.unique()))
)
summary_df["geometry_types"] = (
    summary_df["road_id"].map(geometry_types)
)

summary_df = summary_df.fillna(0)

11. Excel·CSV·PNG 자동화

최종 자동화 프로그램은 XODR 파일 하나를 입력하면 분석부터 보고서 저장까지 자동 수행하도록 구성하였다.

XODR 선택 → XML 파싱 → DataFrame 생성 → Summary 구성 → 품질검사 후보 추출 → 그래프 PNG 저장 → CSV 백업 저장 → Excel 보고서 저장 → XLSX 무결성 검사 → 결과 폴더 자동 열기

Excel 자동 저장

with pd.ExcelWriter(
    "Pangyo_XODR_Analysis.xlsx",
    engine="openpyxl"
) as writer:
    roads_df.to_excel(writer, sheet_name="Roads", index=False)
    lanes_df.to_excel(writer, sheet_name="Lanes", index=False)

12. 자동 품질검사 후보

자동 검사는 “확정 오류”를 판정하는 것이 아니라 사람이 확인해야 할 우선순위를 좁히는 역할을 한다.

검사 항목의미주의점
10m 미만 road과도하게 짧게 분할된 road 후보교차로 connecting road는 정상적으로 짧을 수 있음
일반 road인데 driving lane 0주행 가능한 차선 누락 후보도로 용도에 따라 정상일 수 있음
geometry 길이 합계 불일치road length와 planView 구성 검토허용 오차 기준 필요
laneLink 없음junction 연결 관계 검토junction 유형에 따라 예외 가능
중복 road IDID 충돌 가능성대체로 우선 확인 필요
중복 lane ID같은 laneSection 내 ID 중복 후보road·section·side 조합으로 판단

14. 향후 발전 방향

  1. 폴더 일괄 분석: 판교, K-City, 항만 등 여러 XODR을 한 번에 비교

  5. GUI/EXE: 파일 선택, 진행률, 결과 폴더 열기 기능
  6. 항만 특화: 대형 트럭 회전구간, 병목, 차선폭·곡률 검증
  7. 드론 연계: Pix4D → QGIS → RoadRunner → XODR → CARLA end-to-end 파이프라인
